# 問い合わせメール分類 仕様

## 1. 目的

建材メーカーの顧客問い合わせメールを自動分類し、振り分け先と優先度を判断する。

## 2. 分類軸1：内容カテゴリ（単一選択）

- 品番特定
- 廃番対応
- 製品仕様
- 納期在庫
- 不具合クレーム
- 見積
- 施工相談
- その他

## 3. 分類軸2：発信元

`from`（差出人メールアドレス）のドメインを第一の判断材料とし、本文の署名や転送履歴で補完する。

| 発信元 | 判定基準 |
|---|---|
| `external` | 顧客・取引先からの直接の問い合わせ。署名や差出人から社外と判断できる |
| `internal_forward` | 社内の別部署から転送されたもの。転送の経緯が本文に含まれる |
| `dealer_relay` | 流通店が、その先の顧客から受けた内容を相談してくるもの |
| `unknown` | 署名がなく、フォーム経由など発信元を特定できないもの |

判定順序（`from` のドメインで判定する）：

1. 社内ドメインか → `internal_forward`
2. 流通店ドメインか → `dealer_relay`
3. フォーム等のアドレスか → `unknown`
4. それ以外 → `external`

判断が分かれる例：

- 流通店の担当者が顧客のメールを転送してきた場合は、本文に転送履歴があっても `dealer_relay` とする。返信先が流通店であるため

### ドメイン一覧

| 区分 | ドメイン・アドレス | 発信元 |
|---|---|---|
| 自社 | `kenzai-maker.co.jp` | `internal_forward` |
| 流通店 | `yamada-shoji.example.net`、`kanto-kenzai.example.net`、`marui-sangyo.example.net` | `dealer_relay` |
| フォーム経由 | `noreply@web-form.example.com` | `unknown` |
| 社外顧客 | `〇〇.example.jp` 形式（上記以外すべて） | `external` |

流通店とフォームのアドレスは一覧で管理し、追加があればこの表を更新する。

## 4. カテゴリ定義

| カテゴリ | 定義 |
|---|---|
| 品番特定 | 製品名も品番も不明で、対象製品を特定したい |
| 廃番対応 | 廃番に関する問い合わせ全般（廃番かどうかの確認、代替品・後継品の依頼）。対象製品は特定済み |
| 製品仕様 | 仕様確認、および廃番が前提でない同等品・グレード比較 |
| 納期在庫 | 在庫の有無、出荷日、リードタイムの確認 |
| 不具合クレーム | 製品の不具合、施工後の仕上がり不良、対応への苦情。原因が製品か施工か不明な場合もここに含む |
| 見積 | 数量を伴う価格提示の依頼 |
| 施工相談 | 取り付け・施工の方法（下地、工具、手順、他部材との取り合い） |
| その他 | 担当者確認、挨拶、製品と無関係な連絡など、他の7カテゴリに該当しないもの |

## 5. 境界ルール

- 製品名または品番で対象製品を特定できていれば「判明」とみなす
- 品番特定と廃番対応の境界は「対象製品が判明しているか」
- 廃番が前提でない比較は製品仕様
- 製品仕様と施工相談の境界は「製品の情報を聞いているか、使い方を聞いているか」
  - 例：他部材との取り合い（シーリング等）に関する推奨値の質問は施工相談
- 見積と製品仕様の境界は「数量を伴う価格提示か、単なる価格情報（定価など）の確認か」

## 6. 複合メール

実データの約7割が複合（複数の用件を含む）。優先順位ルールで主要件を1つ選ぶ。

```
不具合クレーム > 納期在庫 > 品番特定 > 廃番対応 > 見積 > 製品仕様 > 施工相談 > その他
```

## 7. スコープ外

- 1通単位の分類とし、スレッド単位の文脈保持は対象外
- マルチラベル化は次段階の課題
